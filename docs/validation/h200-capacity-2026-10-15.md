# H200 capacity adaptation validation — 2026-10-15

> Historical pre-accumulation evidence: these runs used the selected microbatch as global batch. They remain memory measurements of that revision, not validation of the current fixed-global-batch accumulation path.

The single-GPU 80 GiB workflow passed with **batch 64**. A separate 48 GiB request hit OOM in the batch-64 GAN phase, automatically retried batch 32, and passed all three phases with **batch 32**.

Hardware: one NVIDIA L20X (H200-class, compute capability 9.0), CUDA-visible memory 139.81 GiB, driver 570.148.08. The experiments used the existing local ImageNet training subset and pretrained inputs without downloading or modifying them. Each phase ran eight real training steps, with the first three excluded from diagnostic step-time summaries. Checkpoint writing, EMA image sampling and evaluation were disabled in the probes.

| Requested budget | Selected batch | Phase | Allocator peak (GiB) | Reserved peak (GiB) | Sampled whole-device peak (GiB) |
|---|---:|---|---:|---:|---:|
| 80 GiB | 64 | Reconstruction + LPIPS | 41.09 | 43.31 | 44.61 |
| 80 GiB | 64 | Discriminator updates | 39.90 | 43.10 | 44.39 |
| 80 GiB | 64 | GAN generator + discriminator | 48.46 | 52.60 | 53.90 |
| 48 GiB | 32 | Reconstruction + LPIPS | 26.05 | 27.66 | 28.96 |
| 48 GiB | 32 | Discriminator updates | 24.74 | 26.35 | 27.65 |
| 48 GiB | 32 | GAN generator + discriminator | 29.05 | 31.19 | 32.49 |

The 48 GiB request reserves 4 GiB outside PyTorch, so its allocator limit is 44 GiB. Batch 64 failed in GAN at that allocator limit, with 45.08 GiB sampled whole-device usage. This is an allocator-limit OOM, not a claim that a physical 48 GiB card had already used all its VRAM. Batch 32 then passed reconstruction, discriminator and GAN, including finite losses and final active-model gradients/parameters.

No new graphs were compiled after warmup in the successful unprofiled runs. The short step times in the JSON are diagnostics on this H200-class device, not A100 performance predictions or a revalidation of the historical 5.32x speedup.

## Environment and tooling exercised

An isolated venv reused the existing read-only working Python environment via `--system-site-packages`. This was not a clean installation of downloaded wheels. `requirements-adapt.txt` was checked against that environment with `pip install --no-index`, and `pip check` passed. The environment preflight imported the real training entrypoint and exercised Inductor forward/backward, cuDNN SDPA and Flash SDPA.

- Python 3.10.22; torch 2.8.0+cu128; torchvision 0.23.0+cu128; Triton 3.4.0.
- transformers 4.56.2; timm 0.9.16; numpy 1.26.0; OmegaConf 2.3.0.
- gcc/g++ and nvidia-smi were available. ninja, nsys and ncu were absent from PATH and were not needed for capacity probing.
- A deliberately missing discriminator checkpoint stopped preflight before CUDA compilation.
- CPU tests passed for phase/config isolation, monitored budget-overrun termination, and timeout termination. The skill validator passed.


A separate 80 GiB / batch-64 diagnostic run exercised `--profile` on the final runtime source. All three phases passed and produced readable Chrome traces with CUDA kernel events plus operator tables. Profiler timings are excluded from the unprofiled capacity table above.

## Scope and provenance

The original optimized source is snapshot `fd7800d0633a`, imported on top of upstream commit `a4d18c4db766419cbe7cb8c02cd9f7ceb0ec9041` in repository commit `649d0e7`. The probe uses the same mathematical optimization preset. The machine-readable record stores source fingerprints for the runtime/tool versions used; additive launcher/validation bookkeeping accounts for the two source fingerprints between the initial 80 GiB trial and later trials.

The actual GPU remained H200-class in every run. The limit applies to the caching allocator; whole-device usage is sampled, not hardware-partitioned. These results establish short-run capacity and the OOM fallback workflow. They do not establish actual A100 compatibility, full-training quality, resume correctness, evaluation/checkpoint memory, multi-GPU behavior, or equivalence to global batch 512. The generated single-card batch changes the training setup.

[Aggregate machine-readable results](h200-capacity-2026-10-15.json) retain all attempted phases. Detailed logs, traces and machine-local configurations remain on the test machine.
